# allsfair-game

Allsfair — a game of simultaneous, predetermined moves. This repo is the whole
thing: game rules, bot, API, and frontend. Live at
[allsfair.hightower.space](https://allsfair.hightower.space/).

One Cloudflare Worker serves everything:

- `GET /*` — static frontend (`public/index.html`)
- `POST /api` — game API (`create_game`, `join_game`, `submit_move`, `get_moves`)
- D1 (SQLite) stores games and moves; board state is derived by replaying the
  move log

## Game rules

`src/engine.ts` is the canonical definition of the game rules. It began as a
port of the
[`allsfair-python`](https://github.com/fhightower/allsfair-python) engine,
which is now archived; this repo is the source of truth.

`test/fixtures/parity.json` was generated by that Python engine and is now a
golden-file regression suite: `test/parity.test.ts` replays 8 scenarios
(3 scripted, 5 seeded 20-round playouts) and asserts board state after every
move pair plus final HTML. It covers long multi-round sequences — restock,
clamping, full render — that the unit tests in `test/engine.board.test.ts` do
not. Keep it passing. A deliberate rules change means regenerating it from
`src/engine.ts` (replay loop → serialize → `toHtmlTable`); there is no longer
an upstream generator.

## Bot

Play-against-bot ships: `create_game` with `play_against_ml` seats a trio-search
bot (`src/bot.ts`) as player 2. Each round it generates candidate trios, plays
each against a set of guessed opponent trios using the real engine, and keeps
the one with the best worst-case-weighted outcome.

The constants at the top of `src/bot.ts` carry their own notes on what is
measured and what is a judgement call — the search sizes were swept, the
action-scorer weights were swept and turned out not to matter, and the
defensive terms are kept on judgement rather than on any win-rate gain.

`test/bot.strength.test.ts` gates strength against random, greedy-heuristic,
pre-tuning, and human-style opponents, from both seats. To measure rather than
just gate:

```shell
BOT_SWEEP=1 npx vitest run test/eval/sweep.test.ts --reporter=verbose --silent=false
```

`test/eval/` holds the harness, the opponent pool, and a frozen copy of the
pre-tuning bot to A/B against. Both vitest flags are needed or the output is
swallowed.

## Development

```shell
npm install
npm test        # vitest; D1 is stubbed with node:sqlite (see test/d1-shim.ts)
npx tsc         # typecheck
```

Note: `wrangler dev` and miniflare need workerd, which requires macOS 13.5+ or
Linux. On older machines the test suite still runs (plain node), and real-runtime
verification happens against the deployed Worker.

## Deploy

```shell
npx wrangler deploy
```

Schema changes go in `migrations/`, applied with:

```shell
npx wrangler d1 migrations apply allsfair --remote
```
